# 4D Attention Mask for Training

## Overview

This folder contains the implementation for using 4D attention masks during training
(policy gradient update), in addition to the existing usage during `compute_log_prob`.

**Status**: Ready but NOT enabled. To enable, apply the patch in `dp_actor_4d_patch.py`.

## Background

The existing codebase already generates `attention_mask_4d` during multi-turn rollout
via `attn_mask_utils.py`. This mask enforces Markov-style visibility rules:

- **Thinking tokens (step j)**: can see question + response/info from step j-1
- **Response tokens (step j)**: can see question + response/info from j-1 + thinking at step j
- **Info tokens**: only attend to themselves (external information, model shouldn't attend to them)

Currently the 4D mask is used during:
- `compute_log_prob` (via `dp_actor.py:_forward_micro_batch`)

But NOT during:
- `update_policy` (only uses standard 2D attention_mask)

## What This Patch Does

Adds `attention_mask_4d` to `update_policy`'s `select_keys` so the 4D mask is also
used during the PPO policy gradient forward pass. This ensures the model "sees" the
same attention pattern during training as it does during inference.

## Files

- `dp_actor_4d_patch.py` — Patch showing the exact changes to `dp_actor.py`
- `enable_4d_training.sh` — One-command script to apply the patch
- `disable_4d_training.sh` — One-command script to revert

## How to Enable

```bash
bash improvements/4d_mask/enable_4d_training.sh
```

## How to Disable

```bash
bash improvements/4d_mask/disable_4d_training.sh
```

## Considerations

- **Memory**: 4D mask is `[B, 1, S, S]` bool. With S=4096, each sample is 16MB.
  Micro-batch of 6 → 96MB extra per GPU. Should be fine with 80GB A800s.
- **Speed**: Negligible overhead — HuggingFace models natively support 4D attention masks.
- **Correctness**: The mask is already generated by the rollout pipeline. This just
  ensures consistent attention patterns between inference and training.
- **Not compatible with `use_remove_padding=True`** (flash attention varlen mode).
  We use `use_remove_padding=False` so this is fine.
